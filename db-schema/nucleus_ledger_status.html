What the schema supports

11 areas

Every card below is scoped by org via Row Level Security — nothing here relies on the application layer to keep tenants apart.

Tenancy & access control

Live
  • Multi-tenant by design, isolated at the database layer
  • Platform superadmins, cross-tenant, granted only via direct SQL
  • Three independent gates: ban switch, base-plan status, add-on entitlement
  • Owner / admin / member roles per org

Business types & onboarding

Live
  • Seeded catalog: Retail, Pharmacy, Restaurant, Distributor, Services
  • Advisory add-on recommendations per type — never enforced

Add-on marketplace

Live
  • Priced catalog, each with a minimum commitment period
  • Full subscribe/cancel history — cancelled rows kept, not deleted
  • Guarded functions only — an org can never self-grant an entitlement
  • Renews on the base-plan cycle, not independently
Public pricing calculator planned on top of this — see below.

Parties

Live
  • Customers & vendors with structured address, tax ID, notes
  • Full audit trail — created_by / created_at throughout

Catalog & inventory

Live
  • SKU, HSN/SAC, unit, reorder level, tax rate per item
  • Multi-warehouse stock, always derived, never hand-edited
  • Append-only ledger — corrections are offsetting entries, never edits
  • Real movements only ever written by the system, not the client

Sales

Live
  • Auto-numbered invoices, auto-computed totals
  • Status machine — paid can only be earned by a recorded payment
  • Line items lock once confirmed — void & reissue, never silently edited
  • Named, dated discount schemes with real date-window enforcement

Sales returns

Live
  • Credit notes tied to the original invoice, own numbering
  • Restocks on issue, reverses on void
  • Return quantity checked against what's actually left unreturned

Purchases

Live
  • Vendor + warehouse + our number + the vendor's own reference number
  • Same auto-computed totals & earned-status pattern as sales

Purchase returns

Live
  • Debit notes tied to the original bill
  • Destocks on issue, same over-return protection as credit notes

Local delivery

Live
  • One delivery per invoice — address, assigned person, status
  • Delivery person is a simple per-org dropdown, not a login role
  • COD / prepaid is a label only — no payment collection wired to it
  • Core feature — not gated behind an add-on
Applied via a standalone patch, same convention as the superadmin patch in v2.

Public pricing calculator

Live
  • Catalog tables now readable by anonymous visitors, not just signed-in users
  • Defaults to the recommended add-ons for the visitor's business type
  • Reads directly from the existing add-on catalog — no new tables needed
Frontend build (the actual calculator UI) is still ahead — the data access it needs is ready.
